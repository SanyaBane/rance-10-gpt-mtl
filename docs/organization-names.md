# The faction on the back of a card

`Belong` is a label baked into the card's overlay CG and was translated with the
rest of the images. The word after it was not: it is a string the `.ain` picks
by number, and it stayed Japanese — `亜人`, `その他` — on the one card face that
draws it.

This is how it was translated, and it is the awkward case of the three that end
in a generated `.jaf`: the string is not merely shared, the *function* is, and
almost every caller is using it as half of a file name.

## Where the word comes from

`getOrganizationNameFromId` (FUNC 28857) is a switch over 所属 1..10:

| id | word | id | word |
|---|---|---|---|
| 1 | 主人公 | 6 | ＪＡＰＡＮ |
| 2 | リーザス | 7 | その他 |
| 3 | ヘルマン | 8 | 亜人 |
| 4 | ゼス | 9 | モンスター |
| 5 | 自由都市 | 10 | 神魔 |

`Party::OrganizationIdFromString` (FUNC 27830) names the same ten in the same
order, which is where the table can be read a second time.

## Why the function cannot return English

Nineteen places call it. **Eighteen paste the result into a CG name:**

```
シス／カード／下地／%s所属          the card background, and its 枠 frame
シス／カード／下地／%s所属／アイテム   the item variants of both, and the ／小 ones
シス／カード／名札／%s所属          the plate the card's name sits on
シス／キャラ詳細／所属旗／%s所属      the flag on the character detail screen
シス／デッキ編成／タブ／%s所属        the deck screen's faction tabs, and ／タブ枠／
シス／クエスト／有利所属／%s所属      the quest screen's advantage panel
```

Translate the function and every one of those lookups misses. The card would
draw with no background at all.

It is worth noticing *why* there are so many: the faction is something the game
shows as a **picture** almost everywhere, and the pictures that carry words are
translated already, as images, under `archives/Rance10CG2_v1_04/`.

The nineteenth caller is a single `ConstructProcess::BlendText` in
`CardConstructProcessCacheBackCard@Create` (FUNC 23037), at (198, 86). That is
the only place in the whole game where a faction is drawn as text.

The same reading of `getElementNameFromId` gives the same shape — sixteen
callers, fifteen of them CG names (`シス／カード／属性／%s`,
`シス／戦闘／弱点属性／%s`), and one `BlendText` in the same function, at (84, 41).
The element is left in Japanese on purpose; it is one glyph and the icon beside
it already says which.

## What is patched

The call, not the function. `patches/card_back_names.jam` replaces FUNC 23037
with its own body verbatim except for three instructions:

```
	.LOCALREF proc                    .LOCALREF proc
	.LOCALREF orgName        -->      .LOCALREF card
	A_REF                             PUSH 28097
	                                  CALLMETHOD 0
	                                  CALLFUNC OrganizationEnglishName
```

`orgName` — the local the five CG names above are built from — is simply not
read any more. Nothing else in the function changes, and nothing anywhere else
in the game does.

`OrganizationEnglishName` is generated by `modules/OrganizationNames.js` into
`build/organization_names.jaf` from `glossaries/organization_name_glossary.tsv`,
keyed by the Japanese. A row left blank returns the game's own word, so a
faction nobody translated falls back to what the card always drew.

### The Japanese build calls it too

`--text-lang=jp` renders the same function with the game's own ten words in it.
That is not decoration: `features/base-stats-on-card/base_stats_on_card.jam`
carries the same body (see below) and is applied in a Japanese build like any
feature, so the function has to exist there. Rendering it with Japanese makes
that build's card back byte-for-byte what it always was.

`scripts/ain.js` renders and passes the `.jaf` when the build applies anything
at all — a translation, or any feature. `--text-lang=jp` with no features stays
the game's own `.ain` byte for byte, which is checked by `cmp`.

## Two `.jam` on one function

This is the only place in the repository where two patches replace the same
function, and it is worth understanding before a third one is written.

alice-tools applies the **last** `--jam` it is given and says nothing about the
earlier one — the same trap as a duplicate `s[N]`, one level up.
`scripts/ain.js` hands it the English first and the features last. So:

| build | which copy of FUNC 23037 runs |
|---|---|
| English, feature on | `features/base-stats-on-card/base_stats_on_card.jam` |
| English, `--without=base-stats-on-card` | `patches/card_back_names.jam` |
| Japanese, feature on | the feature's, with the `.jaf` returning Japanese |
| Japanese, no features | the game's own |

Neither file can be dropped. Merging the translation into the feature would mean
`--without=` costs somebody the English, which is the rule
`patches/enemy_panel_cards.jam` exists for. Leaving it out of the feature would
mean turning the feature on puts the Japanese back.

So both carry the same body, in two regions marked

```
; >>>>>> SHARED CARD-BACK BODY -- HEAD
; <<<<<< SHARED CARD-BACK BODY -- HEAD
; >>>>>> SHARED CARD-BACK BODY -- TAIL
; <<<<<< SHARED CARD-BACK BODY -- TAIL
```

and `modules/CardBack.js` compares them line by line at the start of every
build, naming the first line that differs. Edit one file and the build stops
until the other says the same thing. What sits *between* the two regions is the
feature, and is the only thing the two files disagree about.

Generating both from one source would remove the duplication and was not worth
it: the shared body is a verbatim disassembly that nobody edits by hand twice in
a row, a comparison catches the same mistake, and a generated `.jam` is a file
nobody can read in a diff.

## Width, and why nothing measures it

The line is right-aligned at x=198 on a 208-wide card and the `Belong` label
baked into `シス／カード／詳細` ends at x=67, so a word has about **131px**. It is
drawn at font size **20** where the game drew it at 25: at 25 the longest of the
ten do not fit, and every shortening that would is worse than the smaller type.
`patches/card_back_names.jam` sets 20 for this one line and puts 25 back before
the card's name is drawn with the same `FontProperty`.

**There is no width check.** There was one, and it was wrong: it called
`Gods/Demons` seven pixels too wide, and the card in the game has room to spare.
It was taken out rather than tuned, and this is what it was wrong about, because
the same measure is used elsewhere.

`game/extracted/font_advances.v1.04.tsv` is the **first of forty-one blocks** in
`Rance10Font.fnl`, and `modules/GameFont.js` scales it to any font size by
treating its full-width advance — 45 — as one em. The blocks are a ladder of
raster sizes, and the proportions inside them are not constant:

| block | full-width | `M` | `M`/em |
|---|---|---|---|
| 0 — the one in the table | 45 | 44 | 0.98 |
| 5 | 73 | 61 | 0.84 |
| 10 | 101 | 80 | 0.79 |
| 20 | 157 | 113 | 0.72 |

0.98 is what the smallest raster does when every advance rounds up to a whole
pixel, not what the face looks like. Scaling that block *down* to font size 20
overstates the line by something like half again, which is exactly the error
that showed here.

Which means `gameTextWidth` overstates elsewhere too — `docs/synopsis-screen.md`
put 597 captions across two rows on the strength of it, and some of those may
have fitted one. That is not a constant to nudge inside a faction glossary;
`docs/text-width.md` is where it belongs, and its "Measuring it again" section
is the method. The likely shape of the fix is *pick the block for the size*
rather than scale block 0.

So the instrument for this file is the card on the screen: add a faction, build,
look at it. Ten rows is not a thing that needs a machine, and a machine that is
wrong about them is worse than none.

### The one row no table settles

`神魔`. The prose rendering in this repository is "Gods & Demons" —
`glossaries/card_name_glossary.tsv` has it for the card 伝説の武具神魔 — and it is
too long for the line by any reading. `Gods/Demons` is that shortened to the
closest thing keeping both halves, and it was confirmed on the card. Shorter, if
it ever has to be: Deity, Gods, Divine, Shinma, Demons, Divine Ones.

## Where the rest of the English comes from

Tables that already existed: `亜人 → Demi-Human` and `モンスター → Monsters` are
`glossaries/race_name_glossary.tsv`'s renderings put in the register a faction
label wants — the race glossary answers "what is this enemy", singular, where a
faction is a group; `自由都市 → Free Cities` is `glossaries/summary_glossary.tsv`,
`主人公 → Protagonist` is `glossaries/summary_terms.tsv`, and the three country
names are `glossaries/mistranslated_names.json`.
